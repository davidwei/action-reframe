# Standalone video-leveling system

The system accepts a constant-frame-rate video and a maximum processing-time budget.
It outputs evidence-backed per-frame rotation annotations rather than rendered video.
The implementation lives under `standalone/video_leveling` and does not import the
action-reframing tracker, analyzer, queue, or renderer.

The first deployment uses Gemma 4 for broad visual sampling because it was 2.1 times
faster than Qwen3.8 in the controlled leveling comparison. It uses Qwen3.8 only on
intervals that remain uncertain after background-motion analysis. Model direction text
is excluded; signed rotation is always computed from selected line coordinates.

## Runtime-budget behavior

A six-hour budget is an upper bound on charged processing for one video. Work is spread
over the entire playback timeline before refinement begins. For long slow-motion clips,
sampling frequencies refer to playback time, not the original sensor capture rate.
The current allocation is:

| Stage | Budget | Purpose |
|---|---:|---|
| Decode preparation | 10% | Resumable source validation and sparse image extraction |
| Gemma primary pass | 40% | Absolute horizon/shoreline anchors across the full video |
| Optical motion | 30% | Up to two 5 FPS background-rotation passes |
| Gemma refinement | 7.5% | Add anchors around inconsistent intervals |
| Qwen3.8 review | 7.5% | Re-evaluate the remaining difficult anchors |
| Export | 5% | Solve, shard, checksum, and report the timeline |

The system may finish earlier. It saves each decoded chunk, model response, motion shard,
and annotation shard atomically. On restart it validates checksums and resumes. A damaged
frame keeps its source index and receives a null angle with a review flag. The initial
schema requires CFR input so `frame` and `time_seconds` remain unambiguous.

## Evidence model

Visual-model outputs are absolute but sometimes biased by shoreline perspective or a
wrong reference. Optical estimates capture relative change but drift and can fail over
water or foreground motion. The offline solver combines them: visual anchors bound drift,
while reliable background motion constrains frame-to-frame evolution. It does not bridge
long decode gaps or claim a supported level too far from an anchor.

The output quality field is an evidence score, not a calibrated probability or physical
ground truth. Consumers must preserve null angles and review flags. The raw source image
coordinate space and counterclockwise correction convention are recorded in the manifest.

An optional user scene hint is stored in the immutable job configuration and appended to
the visual prompt. It may identify expected scene classes such as open ocean, shoreline,
or indoor structural lines. The prompt explicitly treats it as recognition context rather
than measured geometry, so visible evidence and null results remain authoritative.

## Model selection and cache boundaries

Primary and review models are explicit configuration fields. An OpenAI-compatible server
can be supplied directly, or the guarded orchestrator can load local weights. All videos
complete a model phase before the next model is loaded. The orchestrator verifies exact
served model IDs, pauses active inference-dependent queue services, and restores and
verifies the production model before resuming them.

Changing either model requires a new output directory. The source fingerprint, effective
settings, prompt version, and model identity are part of cache keys and output metadata.
Decoded source chunks can be copied into a new job in a future optimization, but v1 avoids
implicitly sharing artifacts across incompatible jobs.

## Initial long-video examples

The machine-local run plan configures both `dji_mimo_20260828_*_slowmotion.MP4` files with
six hours each, Gemma 4 primary analysis at up to 0.5 FPS, Qwen3.8 review, and 5 FPS optical
motion. Outputs are written under `outputs/video_leveling`; the plan itself remains outside
Git because it contains machine paths. The static report for each completed job is served
by the existing review service under `/files/outputs/video_leveling/.../report.html`.

Multi-day jobs run as an enabled systemd user service generated by
`standalone.video_leveling.make_service`. The service survives reboot, resumes from
saved stage artifacts, and restores the production model and paused queue through its
stop hook when the worker exits.

Action Reframe consumes the annotation through `leveling_source: annotation`. The adapter
validates schema, source size and modification time, frame count, angle convention, and
every shard checksum. Unsupported frames remain marked in review data; the numeric camera
path interpolates them only because tracking and rendering require a correction at every
frame. The Folder library exposes a Leveling button only when supported gyro is absent;
`/leveling` owns the setup, queue controls, and CPU-only raw/leveled review before
object analysis. Object tracking remains focused on subject labels and tracking results.
